# 项目版本管理规范

当前项目版本为 **0.2.0-alpha.3**，包含图片/视频功能页、中英双语、拖拽上传及任务控制；此前 **0.2.0-alpha.1** 为离线检测与跟踪先导，**0.1.0** 表示2026年10月27日的五页面静态原型和文档基线。该编号不表示上传、推理或实验功能已经完成。当前UI入口见 `web/README.md`。

## 代码与接口

- 在 Git 中跟踪源代码、配置、数据字典、转换脚本、评估适配器和文档；不提交原始数据、模型权重、缓存、密钥或生成媒体。
- 每个已确认可复现的阶段打版本标签。采用 `MAJOR.MINOR.PATCH`：不兼容接口或结果结构变更增加MAJOR；向后兼容的功能增加MINOR；修错和文档修正增加PATCH。预览版本使用`-alpha.N`或`-rc.N`后缀。
- 每次实现状态或验收变化时更新 `CHANGELOG.md`、本规范和相关proposal／报告。实现版本不得高于实际证据支持的状态。
- Python依赖在环境稳定后生成并保存锁文件；训练、转换和评价配置保存在版本控制中。记录Python、PyTorch、CUDA、Ultralytics、OpenCV、跟踪器和评价工具版本。

## 数据集与标注修复

- 原始下载内容写入 `model/data/raw/`，只读保留，不覆盖、不手工修补。
- 每次修复或转换建立新数据版本，例如 `visdrone-det-car-bus-truck-r01`。将版本号、数据来源和许可记录、下载日期、文件SHA-256、样本清单、类别映射、忽略区域规则、训练／验证／测试划分、转换脚本版本及抽查结论写入 `model/data/manifests/<dataset-version>.json`。
- 标注修改必须导出为新版本，并保存修改记录或差异清单。验证集用于调参；最终测试集清单冻结，不能因观察测试结果而反复修正后继续把它当作独立测试。
- 图像、视频及标注文件不纳入普通Git提交。使用清单与内容哈希识别数据；如需复制到另一台设备，先确认数据许可和存储空间。

## 模型与实验

- 每次训练使用不可复用的运行ID，例如 `det-visdrone-20261027-001`；训练权重不得静默覆盖。
- 每个模型版本记录：模型架构／任务、上游权重来源与SHA-256、训练代码Git提交、数据集清单SHA-256、完整配置、随机种子、环境锁版本、设备信息、训练日志、验证指标和权重SHA-256。
- 大体积权重存放在本机 `model/weights/`；版本控制只保存模型清单及其哈希。示例清单为 `model/configs/model_registry.json`，每项都要能指向权重和 `model/experiments/` 中对应的训练记录。
- 只有通过固定验证流程并完成独立测试的模型，才可标为候选发布版本。应用默认模型的变更应记录兼容的类别表、推理配置和回滚版本。

## 评价与发布记录

- 检测和跟踪结果分别保存，不合并成未定义的综合分数。每个结果文件关联代码版本、模型SHA-256、数据版本、评价脚本／适配器版本、指标配置和运行环境。
- 调参期间只用训练／验证数据；最终测试清单只用于正式报告。指标、运行时和失败样例必须从日志生成，不能手工填写成已测结果。
- 每次项目快照在 `.qa/release_manifest.json` 记录版本号、快照时间、当前Git提交（未提交时写`null`）、核心页面与文档的SHA-256，以及当前实现状态。

## 当前状态

UAV项目目录目前位于父级Git仓库中，但目录尚未纳入父级Git跟踪。版本文件、变更记录和内容哈希清单可以先建立快照；只有经过明确的Git暂存和提交后，才可称为已提交的代码版本。原始数据、模型权重及评估输出仍按以上规则单独管理。

## 第三部分离线最小技术链路进展

2026年11月19日按开发计划草稿第三步跑通离线最小技术链路，项目版本0.2.0-alpha.1。第二部分数据审计和划分的技术准备已完成；许可版本适用性继续待跟进，不再作为整个毕业项目停工条件。既有G1未通过标记不改写成已通过；最终测试清单仍未冻结，未执行训练或最终测试。

使用官方COCO预训练YOLO26l和ByteTrack，实现单张JPEG/PNG检测，以及单个恒定帧率MP4的逐帧检测、视频内临时ID和图像轨迹输出。导出标注图片/视频、逐帧JSONL、检测CSV、轨迹JSON及运行状态；图片不分配轨迹ID。每段视频新建跟踪器；缺帧不补造观测，轨迹只连接连续观测。

开发样本来自未隔离的验证候选：一张DET图片及MOT序列uav0000117_02622_v的连续48帧。短片编码为25 FPS，仅为选定的检查播放速率，原始采集FPS未核实。解码帧号0至47对应源帧号1至48；时间戳来自媒体PTS并以首帧归零。Windows专用环境和Docker均完成CPU/GPU图片、视频运行；媒体、坐标、CSV/JSON、哈希和时间轴检查通过，同进程重复视频记录一致。

24项数据与手算评价测试通过，覆盖完美匹配、ID切换、缺失观测、类别错误、忽略区域、ID 0和空分母。检测采用pycocotools，跟踪采用TrackEval 1.3.0并按类别计算IDF1、HOTA、MOTA和IDSW；这是项目本地忽略规则评价，不是官方VisDrone等价分数。发现整帧无预测时TrackEval断轨计数与手算不一致，故Frag置空，原始值仅供排查，留待第五步核验。

本轮真实预测只用于链路检查。48帧中存在漏检、误检及ID切换；没有bus或truck真值，相关比率标记不适用。参数640、conf 0.25及IoU 0.7为未冻结先导值，不是选优结论；低于0.25的检测未输入此轮ByteTrack低分匹配。耗时和PyTorch峰值显存见docs/step3_minimal_pipeline.md及.qa/step3_verification.json，不当作性能验收或代表性准确率。

现已新增本机离线测试界面（见 web/README.md），接入真实离线流水线；其余四页仍为静态样机。离线测试界面未实现筛选、摘要、训练或评估，也不是正式系统验收。损坏文件记录失败、无目标图片可成功返回空结果；操作系统锁及中断恢复仅用于离线运行。原SRS范围、19项系统验收未执行状态、作者学生导师信息、甘特图及附录保持不变。下一步为第四步模型候选比较与微调，最终测试不参与选优。
