**第一步：固定验收定义和实验范围**

先把需求转成一张验收表，确定：

- 首轮类别及定义，尤其不能把 `van` 自动算成 `car`。
- 图片只检测，录制视频检测并跟踪。
- 本地单用户，同一时间最多一个未结束任务。
- 场景摘要包含哪些固定字段，每个字段依据什么生成。
- 支持的文件格式、长度和分辨率；具体上限由试验确认。
- 模型、跟踪器、参数及评价数据如何记录版本。

**产出：**需求验收映射、类别表、配置初稿、实验记录模板。模型阈值与性能目标此时均标记“待先导试验”。

**第二步：审查数据，建立独立评价集**

先下载少量 VisDrone-DET 和 VisDrone-MOT 样本，再扩大下载：

1. 检查文件、标注框、类别和帧间 ID 是否可读取。
2. 统计三个类别的数量、目标大小、遮挡程度和视频分布。
3. 转换检测标注，并将转换后的框画回原图核对。
4. 保留 MOT 的帧号、目标 ID、忽略区域等评价所需信息。
5. 检查 DET 与 MOT 是否存在相同来源的图像或序列，避免训练数据进入最终测试。
6. 固定训练、验证和最终测试清单；测试集不用于反复选参数。

**通过条件：**标注转换正确、类别含义一致、数据划分可追溯。现成数据通常不要求你从零画框，但不能省略这一步。

**第三步：跑通最小技术链路**

暂时不接网页，先实现：

- 一张图片 → 检测结果图片及结构化记录。
- 一段短视频 → 检测、临时 ID、轨迹记录及标注视频。
- 一段人工可检查的短序列 → 正确计算评价指标。

环境使用项目专用依赖和 Docker，分别记录 CPU/GPU 能否运行、显存占用、耗时及复现命令。

**通过条件：**输出可以打开；帧号、时间戳和坐标一致；每段视频重置跟踪状态；错误不会被写成成功。

**第四步：选择并微调检测模型**

按你“优先电脑端准确性”的要求，**大模型优先进入候选，不预先认定最大版本胜出**：

1. 验证当前安装版本支持的较大 YOLO26 权重。
2. 测量候选模型在你电脑上的显存、推理耗时和可用训练配置。
3. 建立预训练模型基线。
4. 用 VisDrone 训练集微调。
5. 在验证集比较模型大小和输入分辨率。
6. 只有小目标漏检仍突出时，再试切片推理，避免一开始引入过多变量。
7. 冻结模型和阈值，最后才执行最终测试。

**验收证据：**每类 Precision、Recall、mAP50、mAP50–95，以及小目标、遮挡、密集画面的漏检和误检案例。不能只给一个总体分数。

**第五步：优化和评价跟踪**

先固定检测器，再比较跟踪器，防止把检测器变化误认为跟踪算法改善。

- ByteTrack 建立简单基线。
- BoT-SORT 测试相机运动补偿是否有帮助。
- 使用完全相同的视频、检测配置和评价范围。
- 检查遮挡、目标交汇、镜头转动、离开画面等情况。
- 记录 ID 切换、断轨和错误关联，不只挑效果好的片段。

官方文档将 BoT-SORT 列为无人机或移动相机视频的可选起点，但是否优于 ByteTrack，仍要在你的数据上实测。[Ultralytics 跟踪文档](https://docs.ultralytics.com/modes/track/)

**验收证据：**IDF1、HOTA、ID 切换及断轨分析。评价适配必须先核验帧号、类别、忽略区域和坐标，不能仅仅“跑出分数”。

**第六步：实现可核验的场景摘要**

先采用结构化统计加文字模板：

- 当前帧各类可见目标数量。
- 目标在图像左、中、右或自定义图像区域内的分布。
- 指定临时 ID 的首次、末次观测时间。
- 轨迹在哪些时段有真实观测，哪些时段缺失。
- 输出对应时间戳，点击后可以回到证据画面。

这里要分两次验收：

1. **逻辑正确性：**给定结构化检测记录，统计和摘要是否计算正确。
2. **端到端正确性：**与人工标注对照，最终数量、区域关系和时间信息是否正确。检测错误必须计入，不能只证明模板没算错。

**这一版本不必接大语言模型。** 若之后接入，它只负责将结构化结果组织成文字；数值、ID、时间和位置关系仍需由程序校验。自由生成文字不能成为“场景理解正确”的证据。

**第七步：把真实链路接入网页**

沿用现有界面，实现完整流程：

**选择文件 → 输入校验 → 创建任务 → 后台处理 → 生成输出 → 播放与筛选 → 导出。**

重点完成：

- 后端强制执行单任务限制。
- 刷新页面后仍能查询任务状态。
- 无目标、损坏文件、处理失败等都有明确结果。
- 视频暂停和跳转后，框、信息和时间戳对应。
- 类别与 ID 筛选只改变显示，不破坏原始结果。
- 下载的图片、视频、CSV/JSON 与网页数据一致。

当前前端仍是静态样机，这一步才会让它具备真实处理功能。

**第八步：最终验收与报告**

| 验收项 | 必须提供的证据 |
|---|---|
| 识别准确 | 独立测试集指标、类别样本量、误检漏检分析 |
| 跟踪可靠 | 跟踪指标、ID 切换与断轨案例、同条件算法对比 |
| 场景摘要可信 | 人工标注对照、统计误差、每条描述的画面依据 |
| 新视频可用 | 未参与调参的相似航拍视频；无标注时只能说明功能运行，不能声称准确率 |
| 软件完整 | 上传、处理、回放、筛选、导出及错误恢复记录 |
| 可复现 | 数据清单、权重、配置、依赖、Docker 与复现命令 |

**准确率门槛应在先导试验后、最终测试前固定。** “准确识别”不能直接解释成“所有目标都识别正确”，也不能用检测置信度代替准确率。先用代表性样本确定合理门槛，再按冻结后的标准验收，避免根据最终成绩反过来修改标准。

建议十二周安排为：**第 1–2 周完成需求、数据与最小链路；第 3–5 周检测微调；第 6–7 周跟踪评价；第 8 周场景摘要；第 9–10 周网页集成；第 11–12 周独立验收与报告。** 每一步都保留配置、结果、失败原因及下一项决策记录。确认有限场景理解的具体字段后，再将新增范围和模型选型同步到 proposal、SRS、README 和项目说明文档。
